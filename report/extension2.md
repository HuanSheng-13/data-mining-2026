# 拓展任务二：企业财务问答 Agent

本文为初版实验报告，依据已保存的运行与独立评测结果整理，供后续统一核对和完善。

## 问题描述与定义

任务要求设计可复用的大模型Agent，接收公司CIK和英文问题，自主选择查询财务数据库、检索本地年报、计算指标或继续核查，最终给出有依据的英文回答。同一套系统应处理不同公司与问题，无需逐题人工编写SQL或准备答案。

本方案直接通过模型API实现决策与工具调用循环。大模型决定下一步操作，程序执行真实工具调用、返回证据并记录过程；数据准备采用固定流程，答题过程由模型根据工具结果决定，不是固定流水线后仅用模型润色。

## 数据特点与处理

使用老师提供的FinanceQA数据包，包括六家公司的SQLite财务数据库、9份HTML年报及56道英文问题。train包含四家公司37题，test包含另外两家公司19题。数值与跨期指标主要通过SQL查询和计算，业务、战略、风险与会计附注主要通过年报检索获取。

原始数据库、报告、输入输出协议和教师检查器保持不变。所有公司资料可在不使用标签的前提下预处理：提取HTML可见正文及表格单元格分隔，去掉隐藏XBRL等内容，以1,800字符窗口、200字符重叠切块，共生成2,615个片段。每个片段保留公司、报告期、文件、文本位置和稳定ID，并允许补读相邻片段，以缓解表格和段落被截断的问题。

派生产物另存于 `extension2_finance_agent/artifacts/final/`，保存数据库、年报及片段文件指纹，运行前检查输入是否变化。参考答案和评分输出不进入检索索引。独立目录重建约耗时2.23秒，产物与本次使用的索引逐字节一致；此时间为复现测量，不是首次准备耗时，见[准备验证记录](../results/extension2/preparation.json)。

## 方法设计

### 模型决策与工具

采用 `deepseek-flash`，答题温度为0，每题最多16轮模型交互、24次工具调用，单次输出上限3,000 tokens。模型可使用六个工具：

| 工具 | 作用 |
| --- | --- |
| `get_schema` | 查看核心表结构和当前公司年报目录 |
| `discover_metrics` | 发现实际财务指标标签 |
| `query_sql` | 只读查询指标、期间、单位及事实ID |
| `search_reports` | 按公司及可选报告期检索年报片段 |
| `read_report_chunks` | 读取片段邻域，补足表格与上下文 |
| `calculate` | 从返回的操作数执行加减乘除 |

模型收到工具结果后决定继续检索、计算、修正查询或结束。每题创建全新的工具实例和消息列表，不将上一题的回答或中间状态传递到下一题。SQL使用只读连接、授权器及资源限制；计算器只接受标量算术，不执行任意代码。工具均返回统一的结果、来源和错误字段，真实参数、结果与错误写入逐题日志。

### 财务Skill与输出检查

三份参数化财务Skill分别指导指标及期间口径、可比计算与来源、失败恢复与停止。它们要求模型检查单位、重复披露、报告期、会计口径，区分业务领域与财务分部，以及事实、风险和计划，避免直接把结构化标签名称当作财务实质。Skill不包含逐题答案或test反馈。

程序为最终回答保留最后两轮；进入总结阶段后不再提供工具定义。如果模型误将DSML工具调用写入正文，只恢复已注册工具的参数，并实际执行和记录调用。未执行的调用不能充当证据。最终答案若残留工具标记或引用未检索过的完整片段ID，会被拒绝并要求重答；无法形成有效回答时记录失败，不冒充完成。

这些检查约束运行协议和部分引用追溯性，不保证所有财务结论正确。模型仍负责公司、单位、期间和指标口径的选择，简写引用及事实ID也未被全面逐项校验。

## 实验设置与评测协议

开发和方法选择仅使用train及其反馈。历史候选实验保存在Git历史 `e7a8c9c`，当前工作目录只保留选定方案。选择考虑训练集支持率、工具成本与输出可靠性；最终版本同时调整提示、预算和索引，不能将与历史候选的差异解释为只改变单一变量的受控消融，也不能证明其为所有方法中的全局最优。

最终方法在 `7445dd1` 完成train验证，在干净提交 `55e8418` 上冻结后自动完成全部19题test，再运行教师原始 `evaluate.py`。当次验证中，train、test及冻结快照的方法资源和准备产物指纹一致；不使用test参考答案或评分反馈修改方法，不重跑或筛选测试答案。

独立检查器同样使用 `deepseek-flash`，根据原问题、参考答案和保存的回答判定支持、矛盾或信息不足。支持率按完整split题数计算：

$$
\text{支持率}=\frac{\text{获支持的回答数}}{\text{该split全部问题数}}\times100\%.
$$

本次56次评分请求均成功，无需失败重试。自动支持率属于宽松一致性判定，不等于逐句人工审计后的完整正确率，也不直接换算作业分数。

### 未获支持结果与来源核对

三条矛盾判定与原答案全部保留，来源核对不用于修改官方标签。

- `FQA-1373715-06`：答案依据2024年报描述2030年到期的固定利率债券，与参考答案对可转换债务的描述冲突。结构化标签名称也可能与附注中的债务实质不一致，需结合年报判断。
- `FQA-702165-03`：答案引用运输单位数同比增长5%，参考答案描述收入吨英里基本稳定。两个指标的口径不同；答案未提供收入吨英里来消除歧义，不能自行改判为正确。
- `FQA-1800-02`：答案描述2024年报中诊断业务及新冠检测收入下降，与参考答案强调其增长的描述冲突。同时，答案表格未单列Other：四个分部之和为41,934百万美元，加Other 16百万美元才等于净销售额41,950百万美元。来源争议不能作为整篇回答完全正确的证据。

具体核查范围、报告指纹和片段位置见[source_checks.json](../results/extension2/source_checks.json)。这里只针对三条争议做了来源核对，没有逐句人工审计全部56篇回答。

### 工程验证与局限

当前方案37项自动化测试全部通过，覆盖只读SQL、计算限制、数据变化检测、工具协议恢复、最终输出拒绝、每题状态隔离、冻结检查及本地HTTP端到端调用，见[测试记录](../results/extension2/unit_tests.json)。

实际56题记录中出现3次SQL参数绑定错误（train 2次、test 1次），模型收到错误后继续完成。真实批次未触发DSML恢复或最终拒绝，这些分支由合成回归测试覆盖，不能声称已验证其在真实批次中的恢复成功率。

本方案仍有以下局限：词法检索可能漏掉语义相关证据；字符切块可能破坏复杂表格；单位、期间和财务口径仍依赖模型核查；完整片段ID可追溯不等于每项主张都受来源支持。固定温度也不保证外部模型更新后的输出逐字一致。后续若继续探索，应保留本次首次正式测试结果，不将已见test反馈后的调整混同为新的独立验证。
