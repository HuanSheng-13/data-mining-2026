Names alone are not a reliable join key. Discover tag synonyms from the actual database instead of guessing one universal revenue or profit tag.
Retrieve a narrow set of candidate facts with traceability: id, fact_name, fact_category, fact_value, unit, end_date, fiscal_year, fiscal_period, frame, form_type, filed_date and accession_number as needed. Inspect rows before doing a calculation. ORDER BY id or MAX(fact_value) does not establish financial priority. If the query is truncated, narrow the concept/period or fetch another targeted slice; do not silently use the first 100 rows as complete.
Bind each selected fact to its concept, unit and period. Revenue/profit/expense are flows; assets/liabilities/cash are point-in-time balances. An FY label or 10-K can still contain comparative or short-duration facts; inspect frame/end_date and corroborate period length with the report when ambiguous. An empty frame does not imply a full year. The database lacks complete start_date information. Do not turn an unconfirmed quarterly flow into an annual figure.
Do not select the latest quarter when the question asks for a fiscal year. With no explicit period, identify the latest applicable annual report and state its actual period. Once concept, unit, period and scope match, select the latest applicable annual disclosure, retaining its source. Do not SUM duplicates from repeated filings, and do not merge different tags or reported/adjusted values merely because they look similar. NULL is not zero. Conflicting versions require an explicit selection and limitation.
