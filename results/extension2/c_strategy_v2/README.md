## 修订依据与版本

第一轮人工核对发现，C 曾把不同 filing 的 fact ID 统一挂到同一个 accession；同时两个案例尝试将多个表达式交给只支持标量的计算器。第二版只补充通用指导：每次 calculate 只用一个标量表达式，逐条核对 fact ID 与其真实 accession。不按题号加入答案、数值或固定 SQL。

第二轮方法版本 `9453577846f2dc771e9954e400f4a835efbebca5`，两组 run.json 均为同一干净提交，方法文件哈希相同，只有选择的 strategy_factory、prompt_file、skill_files 不同。Python 3.13.1，作答与检查器 deepseek-flash，温度 0、输出上限 2500、12 轮、16 工具预算，基础工具与年报片段不变。回归测试另使用 Python 3.12.14；最终新增比较器测试后为 48 项通过。

## 案例核查

- Norfolk 经营比率与利润率两题：抽查 11 个实际引用 fact ID，全部属于回答列出的 `0000702165-25-000008`，原始 USD 数值与日期已只读核对，见 `case_audit.json`。不是只看答案里写“核对过”就当作完成。
- C 的六题日志没有多表达式 calculate 报错；但利润率题首次 SQL 将 CIK 写成字面量却仍附加一个 params，导致绑定数量错误，随后修复。这说明错误恢复有效，但提示词无法保证零错误。
- C 利润率回答仍把 adjusted 2024 与 reported 2022 并置解释，不能当作干净的同口径比较；该表述风险被宽松支持评分遗漏。自动支持不是每句话都正确的证据。
- 基础策略本轮也能形成正常最终回答，第一轮的两个伪工具正文没有重现。因此不能声称 C 必然带来 33.33 个百分点提升，也不能把首轮基础失败当作稳定弱基线。

## 两轮结论与验收边界

第一轮基础 4/6、C 6/6，第二轮均为 6/6。两轮都属于同一个开发子集，第二版还用到了第一轮反馈，不能合并成独立测试集或计算泛化置信度。两轮 C 工具调用均较少（59→55、54→44），总 tokens 方向不一致（388276→307289、306756→321975）。当前可支持的结论是：接口与真实行动可复现、规则可复用且有具体成本权衡；无法凭六题确认总体准确率提升。

两组评分均 evaluation_complete=true、api_failed=0。官方仍把全部 37 题作为分母，31 题缺失计入信息不足；comparison.json 另明确计算六题分母，不能将 100% 写作全 train 成绩。未运行或读取正式 test，不依赖 B 尚未完成的工具。
