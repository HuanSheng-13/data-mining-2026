## 已完成的本地验证

- Python 自动化测试：只读 SQL、越权与写入拒绝、资源限制、错误恢复、算术限制、报告范围、准备指纹、状态重置、模型和工具预算、工厂接口、Skill 载入、冻结约束、本地 HTTP 协议，以及本地 `.env` 解析、优先级、模型和检查器读取与密钥不进入配置快照。
- 真实数据准备：9 份年报，2,787 个基础文本片段，保存数据库与报告指纹。
- 真实工具运行：结构发现、指标发现、SQL 查询、报告检索、计算和写入拒绝共 6 项检查，完整记录见 [tool_smoke.json](tool_smoke.json)。计算使用的 120/100 明确为合成验算操作数。
- 官方格式检查：使用单独标注的格式测试夹具执行老师原脚本的 `--check-only`，验证预测协议和独立评测入口。夹具不是模型回答，不做支持率评分。

自动化记录和实际测试数量见 [verification.json](verification.json)。本地 HTTP 测试中的响应是测试服务器脚本生成的，用于检查通信和数据流，不属于真实模型实验。

## 已完成的真实模型验收

2026 年 11 月 25 日，使用本地 `.env` 配置的 `deepseek-flash` 完成 4 道真实 train demo，全部正常结束。实际调用模型 19 轮、工具 30 次，覆盖数据库结构发现、指标发现、SQL、年报检索和计算；整批作答约 37.06 秒，服务返回累计 166,188 tokens，其中输入 161,357、输出 4,831。用量含多轮重复上下文，不能据此直接计算人民币成本。

老师原始评测程序的格式检查通过，检查器模型对这 4 题均判为 `CORRECT_INFO`，没有 API 失败。原始脚本以全部 37 道 train 题为分母，其余 33 题未作答，因此原始总支持率为 4/37，约 10.81%；单独观察本次作答的 4 题则为 4/4。两种统计口径保留在记录中，均不作为完整 train 或 test 的表现结论，也不等于严格完整正确率。

详见[真实 demo 验收记录](demo_live_v1/README.md)，其中包含预测、逐题结果、实际工具调用、原始格式检查和原始评分报告。自动化摘要见 [acceptance.json](demo_live_v1/acceptance.json)。回归测试仍为 36 项全部通过，原始数据指纹未变，输出中未出现已配置的密钥值。
